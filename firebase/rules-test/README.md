# 규칙 검증 (에뮬레이터 + 모델 비교)

`firestore.rules`는 `core/remote`의 `AccessPolicy`(실행 가능한 모델)를 손으로 옮긴 것이다. 이 폴더는 둘이 **같은 판단**을 내리는지 에뮬레이터에서 확인한다.

## 어떻게
1. `core`의 접근 관련 테스트(전송, 사용자, 방 — 수십 개 시나리오)를 `-Pruletrace=<dir>`로 돌리면, 모델이 내린 모든 허용/거부 판단(쓰기 배치, 문서 읽기, 목록 조회)이
   시간 순서대로 시나리오(테스트)별 JSON Lines 파일에 기록된다.
2. `replay.mjs`가 각 시나리오를 **같은 순서로 실제 규칙에** 던진다(관리자 쓰기는 규칙 없이, 나머지는 해당 사용자 인증으로). 허용/거부가 모델과 다르면 그 테스트 이름과 이벤트를 출력한다.

```
cd core && LC_ALL=C.UTF-8 gradle :remote:test -Pruletrace=/tmp/trace --rerun-tasks   # 추적 기록
cd firebase/rules-test && npm install                                                # 한 번
TRACE_DIR=/tmp/trace npm test                                                         # 에뮬레이터에서 비교 (Java 필요)
```

## 한계
- 규칙이 맞다는 증명이 아니라 **모델이 시도한 시나리오에서 모델과 같다**는 확인이다. 모델에 없는 시도는 비교되지 않는다.
  규칙을 고칠 때는 `AccessPolicy`와 함께 고치고, 새 거부 시나리오는 `core/remote`의 테스트로 추가한다(그러면 자동으로 비교 대상이 된다).
- 규칙 줄 단위 변이 검증(각 `&&` 조건을 `true`로 바꿔 불일치가 생기는지)으로 어떤 조건이 시나리오에 의해 실제로 검증되는지 확인했다(결과: ADR 0008 "검증").
- 목록 조회(`list`)는 쿼리 제약으로 규칙을 만족시키는 경우만 다룬다.
