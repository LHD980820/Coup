# 나중에 고칠 것 (백로그)

오너가 실기기에서 써 보고 모은 개선 사항. **지금은 고치지 않고 기록만 한다.** 항목마다 오너가 한 말, 코드를 확인한 현재 상태, 고칠 때의 방향을 적는다.

> 배포는 당분간 보류(아예 안 할 수도 있음)다. 배포가 필요 없는 개선은 이 목록에서 계속 진행한다.

| # | 항목 | 규모 | 권장 모델 |
|---|---|---|---|
| 1 | UI 가독성·시인성·"게임 같은" 느낌 개선 | 큼 (디자인 방향부터) | 디자인 방향 **Opus**, 구현 Sonnet |
| 2 | 카드 터치 시 확대 (내 카드, 상대의 공개된 카드) | 작음~중간 | Sonnet |
| 3 | 뒤로 가기가 앱을 바로 종료함 | 중간 (모든 화면) | Sonnet |

---

## 1. UI 가독성·시인성 — "게임 같지가 않다"

**오너 의견**: 가독성과 시인성이 너무 나쁘고 게임 같지 않다. 애니메이션 추가 등 UI 개선이 필요하다.

**현재 상태 (코드 확인)**
- 화면은 Material 3 기본 위젯(카드·버튼·텍스트)을 어두운 팔레트에 얹은 **정보 표시 중심** 구성이다(`game/GameScreen.kt`, `ui/theme/`). 배경·테이블·카드 질감 같은 게임 연출이 없다.
- 상대는 150dp 폭의 글자 카드 한 줄(`OpponentCard`), 내 손패는 62×88dp 카드 그림 + 글자, 코인은 "코인 N" 글자다. 카드 그림(`res/drawable/card_*.png`)은 옛 앱의 것이 그대로다.
- 이미 있는 것: 카드 뒤집기·코인 숫자 굴러가기·응답 시트 등장 애니메이션(설정에서 속도 조절/끄기), 남은 시간 링, 효과음, 대화면 2단. 즉 **연출 뼈대는 있고 시각 디자인이 비어 있다.**
- 접근성 기본기(터치 타깃 48dp, 글자 크기 대응, 색만으로 의미 전달 금지)는 갖췄지만 **대비·크기·위계(무엇이 먼저 보여야 하는가)** 는 점검한 적이 없다.

**고칠 때의 방향 (먼저 디자인을 정하고 구현)**
1. 시각 방향 정하기: 테이블(펠트/나무) 배경, 카드 크기·질감·역할별 색, 코인 아이콘, 플레이어 자리(아바타·턴 표시), 글꼴 위계. 목업(스크린샷 비교) → 오너 승인 → 구현.
2. 카드·코인을 글자가 아니라 **그림**으로(코인 더미, 영향력 카드 뒷면 겹침), 진행 중인 사람을 크게 표시.
3. 화면 전환·턴 넘김·도전/막기 같은 **극적인 순간의 연출**(현재는 카드 뒤집기·코인 숫자뿐). 설정의 애니메이션 속도/끄기 규칙은 그대로 따른다.
4. 대비 검사(WCAG AA 이상)와 큰 글씨·작은 화면(320×568dp) 테스트를 함께 유지한다 — 기존 화면 테스트가 이를 지켜 준다.
5. 햅틱 반응(선택).

**참고**: 카드 그림 교체는 저작권/출처 확인이 필요하다(현재 그림의 출처 미확인). 새 그림을 만들 수 있으면 SVG/벡터로 만들어 해상도 문제를 피한다.

## 2. 카드 터치 시 확대

**오너 의견**: 게임 중 내 카드나 상대방의 공개된 카드를 터치하면 확대되는 기능을 추가한다.

**현재 상태 (코드 확인)**
- 내 카드: 카드를 고르는 결정이 아닐 때 탭하면 **역할 능력 시트**가 열리지만 카드 그림은 같은 62×88dp 크기 그대로다(확대가 아니다). 카드를 고르는 중에는 탭이 선택이다.
- 상대의 **공개된 카드**: 34×48dp로 작게 보이고 **탭해도 아무 일도 없다**(역할 이름은 접근성 설명으로만 있다).

**고칠 때의 방향**
1. 공용 `CardZoom`(큰 카드 그림 + 역할 이름 + 이 역할의 행동·막기 설명)을 만들어 내 카드·상대 공개 카드·(필요하면) 결과 화면의 카드에서 같이 쓴다. 지금의 능력 시트와 합치는 편이 단순하다.
2. 충돌 주의: 카드를 고르는 결정 중에는 탭이 선택이므로 **길게 누르기** 또는 카드 구석의 확대 아이콘으로 확대한다. 확대 중에는 시간이 흐르므로 남은 시간 링을 확대 화면에도 보인다.
3. 닫기: 바깥 탭, 닫기 버튼, 뒤로 가기(3번 항목과 같은 규칙).
4. 상대 카드는 누구의 카드인지(이름)와 공개 이유(영향력을 잃음/도전으로 공개)를 함께 보이면 좋다(기록에서 알 수 있다).
5. 테스트: 열기/닫기, 선택 중 탭은 선택, 공개되지 않은 상대 카드(뒷면)는 확대하지 않음, 스크린리더 설명.

## 3. 뒤로 가기가 앱을 바로 종료한다

**오너 의견**: 튜토리얼 목록·튜토리얼 진행 중·게임 중·게임 종료 후 등 거의 모든 화면에서 뒤로 가기를 누르면 앱이 그냥 종료되는 것 같다. 이전 화면으로 돌아가야 한다. (새 Activity에 들어갈 때 이전 Activity를 finish 하는 것인가?)

**원인 (코드 확인): finish가 아니라 "뒤로 가기를 처리하는 곳이 없어서"다.**
- Phase 5(ADR 0018)부터 **Activity는 `MainActivity` 하나**이고(`AndroidManifest.xml`에 `<activity>` 1개), 화면(홈·설정·튜토리얼·랭킹·로비·방·게임)은 Activity가 아니라 `AppFlow`의 **상태(`screen` 변수)로 갈아 끼우는 Compose 화면**이다. 그래서 "이전 Activity"도, 시스템 뒤로 가기 스택도 없다.
- 뒤로 가기를 직접 처리하는 곳(`BackHandler`)은 **멀티플레이 게임 화면 하나뿐**(`GameScreen`의 `backConcedes`)이다. 그 밖에는 화면의 "뒤로" 버튼만 이전 화면으로 보내고, **시스템 뒤로 가기는 처리 없이 Activity로 올라가 앱이 종료된다.**
- 영향 범위: 설정·랭킹·전적·튜토리얼 목록·튜토리얼 진행·싱글플레이 설정·**싱글플레이 게임 중과 결과 화면**·멀티플레이 로비·방 만들기·대기실·로그인.
  멀티플레이 게임 중은 기권 확인 대화상자가 뜨고, 끝난 뒤 뒤로 가기는 나가기로 동작하는 것만 의도대로다.

**고칠 때의 방향 (`AppFlow`에서 한 곳에서 규칙을 정한다)**

| 지금 화면 | 뒤로 가기 |
|---|---|
| 설정·랭킹·전적·싱글 설정·튜토리얼 목록 | 홈 |
| 튜토리얼 진행 중 | 확인("튜토리얼을 그만할까요?") 후 튜토리얼 목록 |
| 튜토리얼 완료 대화상자 | 목록으로 |
| 싱글플레이 게임 중 | 확인(기권/나가기) 후 설정 화면 — **조용히 판을 잃지 않게** |
| 싱글플레이 결과 | 설정 화면(다시 하기와 같은 길) |
| 멀티 로비 / 로그인 | 홈 |
| 방 만들기 | 로비 |
| 대기실 | 방 나가기 확인 후 로비(방장이면 방이 닫힌다는 경고) |
| 멀티 게임 중 / 결과 | 지금 동작 유지(기권 확인 / 나가기) |
| 홈 | 앱 종료(한 번 더 누르기 안내 또는 확인 — 선택) |

- 구현: Compose `BackHandler`(예측형 뒤로 가기와 호환 — targetSdk 36에서 기본 켜짐). 화면 상태를 한 곳에서 가진 `AppFlow`가 현재 화면에 맞는 핸들러를 걸면 화면마다 따로 짜지 않아도 된다.
- 주의: 대화상자가 열려 있을 때는 대화상자가 먼저 닫혀야 한다(능력 시트·규칙 대화상자·기권 확인). 키보드가 열린 입력 화면(로그인·닉네임)도 같은 규칙.
- 테스트: Robolectric에서 `onBackPressedDispatcher.onBackPressed()`로 화면마다 기대한 화면으로 가는지, 홈에서만 종료되는지, 게임 중에는 확인이 먼저 뜨는지. 모든 화면이 표에 있는지를 enum 전체를 도는 테스트로 지킨다(새 화면을 더하고 규칙을 빠뜨리면 실패하도록).
