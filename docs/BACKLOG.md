## 1. UI 가독성·시인성 — "게임 같지가 않다" — ✅ 1차 (2026-11-13)

**구현한 것** (모습과 규칙은 [DESIGN.md](DESIGN.md), 아래 "현재 상태"와 "방향"은 처음 기록한 그대로 둔다):
- **한 가지 모습**: 촛불 아래의 어두운 호두나무 테이블, 황동·금 장식, 역할마다 색과 문양(공작 보라·왕관, 암살자 강철빛·단검, 사령관 파랑·닻, 대사 초록·맞바꿈, 백작부인 붉은색·방패). 밝은 테마는 없앴다.
- **카드**: 역할 색 바탕 + 옛 그림에서 잘라 낸 초상 + 문양 + 글자로 그린 이름. 자리의 작은 카드부터 확대 창까지 같은 그림이고, 잃은 카드는 빛이 바래고 X가 붙는다. 뒷면도 그린다.
  옛 카드 PNG 6장(13.7MB)은 글자가 그림에 박혀 있어 작으면 읽히지 않고 영어에서도 한국어였다 — 초상 5장(약 190KB)으로 바꿨다.
- **게임 화면**: 상대 자리가 옆으로 밀지 않아도 모두 보이고(3 / 2x2 / 3+2), 지금 움직이는 사람이 금색으로 맥박친다. 가운데 무대가 지금 벌어지는 일을 문장(紋章)과 함께 알리고 덱이 놓인다.
  내 카드가 가장 크고, 행동은 칸으로 — **내가 든 역할은 색을 채우고 블러핑은 점선만**. 응답할 때는 시트 하나에 상황·남은 시간(막대)·버튼이 모인다. 기록은 최근 일이 맨 위.
- **코인·아바타·남은 시간**을 글자 대신 그림으로(코인 더미, 자리 색 아바타, 시간 막대). 대상을 고를 때는 **자리를 눌러서** 고를 수 있다.
- **연출**: 자리·문장의 맥박, 고른 카드가 올라옴, 무대 내용 전환, 스크롤 가장자리 흐림. 모두 설정의 속도/끄기를 따른다.
- **문구**: 한국어 조사를 앞 글자에 맞춘다("AI 2이(가)" -> "AI 2가", "나이(가)" -> "내가").
- **홈·싱글플레이 설정·튜토리얼 목록·결과·카드 확대**도 같은 모습으로.
- **확인 수단**: 기기 없이 실제 렌더링으로 화면 PNG를 뽑는 `ScreenshotGalleryTest`(`-Pscreenshots=`), 팔레트 대비 테스트(`PaletteContrastTest`), 자리 배치·응답 시트·행동 칸 테스트(`GameTableTest`).

**남은 것**
- **실기기 확인**: 한글 세리프 제목의 실제 모습(기기 글꼴), 맥박·전환 연출의 체감과 배터리, 시스템 바 아래 배경, 태블릿 2단 배치.
- **멀티플레이 화면**(로그인·로비·방 만들기·대기실·랭킹·전적): 같은 바탕·색을 입었지만 배치는 그대로다.
- **극적인 순간의 큰 연출**(도전 성공/실패, 탈락, 승리), 코인이 날아가는 연출, 햅틱.
- **카드 초상의 출처**는 여전히 미확인 — 직접 그린 그림으로 바꾸는 것이 깔끔하다(`portrait_*`만 갈아 끼우면 된다).

## (처음 기록) 1. UI 가독성·시인성 — "게임 같지가 않다"

**오너 의견**: 가독성과 시인성이 너무 나쁘고 게임 같지 않다. 애니메이션 추가 등 UI 개선이 필요하다.

**현재 상태 (코드 확인)**
- 화면은 Material 3 기본 위젯(카드·버튼·텍스트)을 어두운 팔레트에 얹은 **정보 표시 중심** 구성이다(`game/GameScreen.kt`, `ui/theme/`). 배경·테이블·카드 질감 같은 게임 연출이 없다.
- 상대는 150dp 폭의 글자 카드 한 줄(`OpponentCard`), 내 손패는 62×88dp 카드 그림 + 글자, 코인은 "코인 N" 글자다. 카드 그림(`res/drawable/card_*.png`)은 옛 앱의 것이 그대로다.
- 이미 있는 것: 카드 뒤집기·코인 숫자 굴러가기·응답 시트 등장 애니메이션(설정에서 속도 조절/끄기), 남은 시간 링, 효과음, 대화면 2단. 즉 **연출 뼈대는 있고 시각 디자인이 비어 있다.**
- 접근성 기본기(터치 타깃 48dp, 글자 크기 대응, 색만으로 의미 전달 금지)는 갖췄지만 **대비·크기·위계(무엇이 먼저 보여야 하는가)** 는 점검한 적이 없다.

**고칠 때의 방향 (먼저 디자인을 정하고 구현)**
1. 시각 방향 정하기: 테이블(펠트/나무) 배경, 카드 크기·질감·역할별 색, 코인 아이콘, 플레이어 자리(아바타·턴 표시), 글꼴 위계. 목업(스크린샷 비교) → 오너 승인 → 구현.
2. 카드·코인을 글자가 아니라 **그림**으로(코인 더미, 영향력 카드 뒷면 겹침), 진행 중인 사람을 크게 표시.
3. 화면 전환·턴 넘김·도전/막기 같은 **극적인 순간의 연출**(현재는 카드 뒤집기·코인 숫자뿐). 설정의 애니메이션 속도/끄기 규칙은 그대로 따른다.
4. 대비 검사(WCAG AA 이상)와 큰 글씨·작은 화면(320×568dp) 테스트를 함께 유지한다 — 기존 화면 테스트가 이를 지켜 준다.
5. 햅틱 반응(선택).

**참고**: 카드 그림 교체는 저작권/출처 확인이 필요하다(현재 그림의 출처 미확인). 새 그림을 만들 수 있으면 SVG/벡터로 만들어 해상도 문제를 피한다.

## 2. 카드 터치 시 확대 — ✅ 해결 (2026-11-10)

**구현한 것** (아래 "현재 상태"와 "고칠 때의 방향"은 처음 기록한 그대로 둔다):
- 공용 `CardZoom` 대화상자(`game/GameScreen.kt`)가 능력 시트를 대체한다: 큰 카드 그림(높이 260dp, 그림 원본이 1414×2000이라 선명), 역할 이름, **누구의 카드인지**(내 카드 / 잃어서 공개된 내 카드 / "OO의 공개된 카드"), 역할 능력 설명, 규칙이 표준이 아닌 판에서만 "설명이 다를 수 있다"는 안내.
- 내 카드: 탭하면 확대. 카드를 고르는 결정(카드 고르기·교환) 중에는 **탭은 선택, 길게 누르면 확대**(선택은 바뀌지 않는다). 명령을 보내는 중에도 확대는 볼 수 있고 선택만 잠긴다.
- 상대의 **공개된 카드**: 탭하면 확대(터치 영역 48dp). **가려진 카드는 무엇인지 모르므로 누를 수 없다.**
- 확대 중에도 내 결정의 시간은 흐르므로, 결정이 진행 중이고 마감이 있으면 확대 창에 남은 시간 링을 함께 보인다.
- 닫기: 닫기 버튼, 바깥 탭, 뒤로 가기. 작은 화면·큰 글씨에서는 창이 스크롤되어 닫기 버튼에 닿는다.
- 뒤집기 태그를 누르는 영역(래퍼)으로 옮겨 클릭·뒤집기 진행·접근성 이름이 한 노드에 모이게 했다.
- 테스트 `CardZoomTest` 21개. 변이 21종 중 19종 검출, 나머지 2종(확대 그림 크기, 표준 규칙에서 안내가 항상 뜸)은 테스트를 보강해 검출.
- **실기기에서 확인할 것**: 길게 누르기 감도와 탭의 구분, 확대 그림의 선명도, 큰 글씨에서의 배치.

## (처음 기록) 2. 카드 터치 시 확대

**오너 의견**: 게임 중 내 카드나 상대방의 공개된 카드를 터치하면 확대되는 기능을 추가한다.

**현재 상태 (코드 확인)**
- 내 카드: 카드를 고르는 결정이 아닐 때 탭하면 **역할 능력 시트**가 열리지만 카드 그림은 같은 62×88dp 크기 그대로다(확대가 아니다). 카드를 고르는 중에는 탭이 선택이다.
- 상대의 **공개된 카드**: 34×48dp로 작게 보이고 **탭해도 아무 일도 없다**(역할 이름은 접근성 설명으로만 있다).

**고칠 때의 방향**
1. 공용 `CardZoom`(큰 카드 그림 + 역할 이름 + 이 역할의 행동·막기 설명)을 만들어 내 카드·상대 공개 카드·(필요하면) 결과 화면의 카드에서 같이 쓴다. 지금의 능력 시트와 합치는 편이 단순하다.
2. 충돌 주의: 카드를 고르는 결정 중에는 탭이 선택이므로 **길게 누르기** 또는 카드 구석의 확대 아이콘으로 확대한다. 확대 중에는 시간이 흐르므로 남은 시간 링을 확대 화면에도 보인다.
3. 닫기: 바깥 탭, 닫기 버튼, 뒤로 가기(3번 항목과 같은 규칙).
4. 상대 카드는 누구의 카드인지(이름)와 공개 이유(영향력을 잃음/도전으로 공개)를 함께 보이면 좋다(기록에서 알 수 있다).
5. 테스트: 열기/닫기, 선택 중 탭은 선택, 공개되지 않은 상대 카드(뒷면)는 확대하지 않음, 스크린리더 설명.

## 3. 뒤로 가기가 앱을 바로 종료한다 — ✅ 해결 (2026-11-09)

**구현한 것** (아래 "원인"과 "고칠 때의 방향"은 처음 기록한 그대로 둔다):
- `AppFlow`가 게임이 없을 때 뒤로 가기를 한 곳에서 받는다: 홈이 아닌 화면은 홈으로, **홈에서는 2초 안에 두 번** 눌러야 앱이 꺼진다(첫 번째는 "한 번 더 누르면 앱이 종료돼요" 안내, `DoubleBackExit`).
- 멀티플레이 안쪽부터: 가입·비밀번호 재설정 -> 로그인, 방 만들기 -> 로비, **대기실은 먼저 묻는다**(방장에게는 "방이 닫힌다" 경고, `ConfirmLeaveDialog`).
- 진행 중인 싱글플레이 게임과 튜토리얼은 한 번 묻고(확인 중에 한 번 더 누르면 "계속하기"), 나가면 각각 설정 화면 / 튜토리얼 목록으로 간다.
- 결과 대화상자와 튜토리얼 완료 대화상자의 뒤로 가기는 다음 화면(설정 화면 / 목록, 멀티플레이는 대기실)으로 간다. 결과의 **"나가기" 버튼도 앱을 끄던 것을 홈으로** 고쳤다(이 문서에 없던 같은 종류의 문제).
- **기기에서만 드러나는 문제를 함께 고쳤다**: 대화상자는 별도 창이라 뒤로 가기를 화면의 `BackHandler`보다 먼저 받는데, 결과·버려진 판·튜토리얼 완료 대화상자가 `onDismissRequest = {}`라 뒤로 가기를 삼켰다. 이제 각자 다음 화면으로 보내고 바깥을 눌러서는 닫히지 않는다.
- 테스트(`BackNavigationTest` 13, `BackNavigationMpTest` 11): 기기와 같은 순서(맨 위 대화상자 먼저, `pressBack` 도우미)로 눌러 본다. 새 `Screen`을 더하면 규칙을 정하게 하는 표 테스트. 기존 재접속 테스트 2개도 같은 도우미로 바꿨다. 변이 27종 중 21종 검출, 나머지 6종: 동치 3(더 늦게 등록된 핸들러/대화상자가 항상 먼저 받는 방어적 중복), 터치 1(대화상자 바깥 터치는 Robolectric에서 흉내 낼 수 없어 **실기기 확인**), 보강해 검출 2.
- **실기기에서 확인할 것**: 대화상자 바깥을 눌러도 닫히지 않는지, 예측형 뒤로 가기(Android 16) 동작, 홈에서 두 번 눌렀을 때 종료.

## (처음 기록) 3. 뒤로 가기가 앱을 바로 종료한다

**오너 의견**: 튜토리얼 목록·튜토리얼 진행 중·게임 중·게임 종료 후 등 거의 모든 화면에서 뒤로 가기를 누르면 앱이 그냥 종료되는 것 같다. 이전 화면으로 돌아가야 한다. (새 Activity에 들어갈 때 이전 Activity를 finish 하는 것인가?)

**원인 (코드 확인): finish가 아니라 "뒤로 가기를 처리하는 곳이 없어서"다.**
- Phase 5(ADR 0018)부터 **Activity는 `MainActivity` 하나**이고(`AndroidManifest.xml`에 `<activity>` 1개), 화면(홈·설정·튜토리얼·랭킹·로비·방·게임)은 Activity가 아니라 `AppFlow`의 **상태(`screen` 변수)로 갈아 끼우는 Compose 화면**이다. 그래서 "이전 Activity"도, 시스템 뒤로 가기 스택도 없다.
- 뒤로 가기를 직접 처리하는 곳(`BackHandler`)은 **멀티플레이 게임 화면 하나뿐**(`GameScreen`의 `backConcedes`)이다. 그 밖에는 화면의 "뒤로" 버튼만 이전 화면으로 보내고, **시스템 뒤로 가기는 처리 없이 Activity로 올라가 앱이 종료된다.**
- 영향 범위: 설정·랭킹·전적·튜토리얼 목록·튜토리얼 진행·싱글플레이 설정·**싱글플레이 게임 중과 결과 화면**·멀티플레이 로비·방 만들기·대기실·로그인.
  멀티플레이 게임 중은 기권 확인 대화상자가 뜨고, 끝난 뒤 뒤로 가기는 나가기로 동작하는 것만 의도대로다.

**고칠 때의 방향 (`AppFlow`에서 한 곳에서 규칙을 정한다)**

| 지금 화면 | 뒤로 가기 |
|---|---|
| 설정·랭킹·전적·싱글 설정·튜토리얼 목록 | 홈 |
| 튜토리얼 진행 중 | 확인("튜토리얼을 그만할까요?") 후 튜토리얼 목록 |
| 튜토리얼 완료 대화상자 | 목록으로 |
| 싱글플레이 게임 중 | 확인(기권/나가기) 후 설정 화면 — **조용히 판을 잃지 않게** |
| 싱글플레이 결과 | 설정 화면(다시 하기와 같은 길) |
| 멀티 로비 / 로그인 | 홈 |
| 방 만들기 | 로비 |
| 대기실 | 방 나가기 확인 후 로비(방장이면 방이 닫힌다는 경고) |
| 멀티 게임 중 / 결과 | 지금 동작 유지(기권 확인 / 나가기) |
| 홈 | 앱 종료(한 번 더 누르기 안내 또는 확인 — 선택) |

- 구현: Compose `BackHandler`(예측형 뒤로 가기와 호환 — targetSdk 36에서 기본 켜짐). 화면 상태를 한 곳에서 가진 `AppFlow`가 현재 화면에 맞는 핸들러를 걸면 화면마다 따로 짜지 않아도 된다.
- 주의: 대화상자가 열려 있을 때는 대화상자가 먼저 닫혀야 한다(능력 시트·규칙 대화상자·기권 확인). 키보드가 열린 입력 화면(로그인·닉네임)도 같은 규칙.
- 테스트: Robolectric에서 `onBackPressedDispatcher.onBackPressed()`로 화면마다 기대한 화면으로 가는지, 홈에서만 종료되는지, 게임 중에는 확인이 먼저 뜨는지. 모든 화면이 표에 있는지를 enum 전체를 도는 테스트로 지킨다(새 화면을 더하고 규칙을 빠뜨리면 실패하도록).
