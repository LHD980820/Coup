# ADR 0016: 버려진 판·방 정리와 시드 섞기

## 상태
채택 (2026-10). 오너가 "설계가 필요한 다음 단계(방 정리·서버 시드)를 진행"하라고 했고, 아래 권장안으로 정했다(바꿀 수 있다 — "다른 선택지").
코어 모델·실제 규칙(에뮬레이터)·실제 Android SDK·서버 클라이언트 라이브러리(에뮬레이터)·로컬 함수 실행기에서 검증했다. **배포는 오너 작업**(아래).

## 맥락 (ADR 0015 뒤에 남은 구멍)
1. **시드를 방장이 정했다**: 방장은 게임을 만들기 전에 시드를 미리 돌려 보고 좋은 패가 나오는 시드만 골라 시작할 수 있었다.
2. **판을 버려도 아무 일이 없었다**: 방장 권위 판은 방장이 사라지면 멈추고, 결과가 없으니 레이팅도 바뀌지 않는다 — 지는 방장은 앱을 끄면 됐다.
   방장이 결과 없이 게임 상태를 "끝남"으로 바꾸는 것도 막지 않았다.
3. **방에 생존 신호가 없었다**: 방장이 사라진 대기실이 로비에 계속 남았다.

## 결정
1. **시드 섞기**(`GameSeeds`). 실제 시드 = SplitMix64(방장 시드, 게임 문서의 **서버 생성 시각** 밀리초). 방장은 문서가 서버에 닿는 밀리초를 미리 알 수 없다.
   `createGame`이 생성 시각을 다시 읽어 **실제로 둘 설정**을 돌려주고(시작 경로는 이것만 쓴다), 검증기도 같은 방식으로 섞는다 — 섞지 않고 둔 판은 기록이 맞지 않아 무효.
   게임 시작에 서버 호출이 필요 없다(함수 지연·장애와 무관).
2. **버려진 판**(`GameSweeper`). 모든 판의 모든 결정에 시간 제한(최대 30초)이 있으므로 살아 있는 방장은 기록이 몇 분씩 끊기지 않는다.
   마지막 진행(게임 생성 또는 마지막 기록의 서버 시각)이 **10분** 넘은 진행 중인 판을 서버가 `ABANDONED`로 끝낸다(재접속 — ADR 0012 — 에는 충분한 여유).
   - 레이팅 판이면 **방장만** 패배로 반영한다: 아직 살아 있었으면 꼴찌, 이미 탈락했으면 그 탈락 순위(기록을 다시 돌려 확인). 기록이 맞지 않으면 꼴찌.
     다른 참가자의 레이팅은 그대로다(그들은 판을 버리지 않았다). 지는 판을 버리는 것은 지는 것과 같거나 더 나쁘다 → 버릴 이유가 없다.
   - 비레이팅 판은 `ABANDONED` + 판정 `UNRATED`만 남긴다. 클라이언트는 판정 `ABANDONED`를 `Settlement.Abandoned`로 본다.
   - 규칙: 방장은 **진행 중인 판만** 고칠 수 있고, "끝남"은 **결과 문서를 만드는 같은 배치에서만** 쓸 수 있다(결과 없이 끝난 척해 정리를 피하지 못하게).
     결과 문서도 진행 중인 판에서만 만들 수 있다(정리된 판을 되살리거나 뒤늦게 결과를 쓰지 못하게). 방장 앱은 진행 중이 아닌 판을 이어 가지 않는다.
3. **방 생존**(`RoomStore.touch`, `RoomService.keepAlive`, `RoomSweeper`). 모든 방 쓰기에 서버 시각 `updatedAt`(규칙: `== request.time`).
   대기실 방장은 **3분**마다 시각만 새로 쓴다(내용·준비 그대로). **15분** 넘게 조용한 대기실은 로비 목록에서 숨기고(`RoomService.listOpen`) 서버가 닫는다(참가 코드도 푼다).
   게임 중인 방은 판이 끝났거나 버려진 뒤(방의 마지막 쓰기·판정 시각 중 늦은 쪽) 15분 동안 아무도 돌아오지 않으면 닫는다. **판이 진행 중인 방은 닫지 않는다**(게임 중에는 방을 쓰지 않는다).
4. **정리 함수**(`server/` `SweepFunction`, 2세대 Java 21). Cloud Scheduler가 5분마다 Pub/Sub 주제 `coup-sweep`에 보내면 판 정리 -> 방 정리 순으로 돈다.
   한 판·한 방의 저장소 오류는 그것만 건너뛰고(`Failed`) 기록한다. 함수는 실패로 끝내지 않는다(다음 실행이 다시 본다 — 재시도 폭주 방지). 모든 정리는 트랜잭션 안에서 상태를 다시 확인한다(두 번 돌아도, 정리 순간 방장이 끝내거나 알려도 안전).

## 다른 선택지 (고르지 않은 것)
- **서버가 시드를 정한다**(게임 생성을 호출형 함수로): 가장 강하지만 게임 시작마다 함수 호출(Java 콜드 스타트 수 초) + 함수 장애 = 시작 불가. 밀리초 섞기로 같은 효과를 거의 얻는다.
- **버려진 판을 서버가 끝까지 기본 수로 둔다**(방장 기권 처리 후 나머지 자동 진행): 전원 순위가 생기지만 게스트 순위가 수와 무관한 자동 진행으로 정해진다. 게스트에게 불공정해 버렸다.
- 기준 시간(10분·15분)은 상수다(`GameSweeper.DEFAULT_ABANDON_AFTER`, `RoomLiveness`). 너무 짧으면 잠깐 끊긴 방장이 지고, 길면 게스트가 오래 기다린다.

## 검증
- 시드: 같은 입력이면 같고 1ms만 달라도 다름, 생성 시각이 다르게 적힌 기록은 거부, **섞지 않은 시드로 둔 판은 거부**. 셸의 실제 시작 경로로 둔 판은 검증 통과(기존 판정·재접속 테스트).
- 버려진 판(`GameSweeperTest` 6): 최근 기록이면 그대로(오래전에 만든 판이라도), 살아 있던 방장만 꼴찌·게스트 불변·두 번째 정리 무시, 탈락한 방장은 탈락 순위, 기록 조작 시 꼴찌,
  비레이팅 표시만, 전체 정리는 멈춘 판만(진행 중·끝난 판 불변), 정리 순간 방장이 끝내면 끝난 판이 이김, 옛 정산 대기 삭제, 한 판의 저장소 오류는 그 판만 건너뜀. **변이 11종 모두 검출.**
- 방(`RoomSweeperTest` 4, `RoomStoreTest` +2, 셸 +1): 방장이 알리면 서버 시각·버전만 바뀌고 준비는 그대로, 게스트·닫힌 방 거부, 시각 꾸미기 거부(만들기·고치기),
  로비가 15분 넘은 방을 숨김, 대기실 정리·코드 해제, 정리 순간 방장이 알리면 남음, 게임 중인 방은 진행 중이면 둠·끝난 뒤 닫음, 게임 문서 없이 시작만 된 방 닫음,
  셸: 방장 모델이 조작 없이도 방을 새로 쓰고, 서버가 닫으면 게스트 화면이 "방이 닫혔다"를 받는다.
- 규칙: 모델 재생 시나리오 71개·판단 2,751건 불일치 0. 새 조건 변이(게임 수정 3·결과 1·방 시각 3) **모두 검출** — 처음에 살아남은 2개(결과만 따로 쓰기, 결과 먼저·끝남 나중)는 테스트를 더해 잡았다.
- 실제 Android SDK(`:data` 18): 방 서버 시각·끝남 규칙·섞인 시드로 둔 판의 검증이 실제 규칙에서 통과.
- 서버(`server/` 7): 정리 함수 한 번으로 버려진 레이팅 판(방장만 -20) + 방장 없는 대기실 + 그 판의 방이 닫힘, 다시 돌아도 불변. 배포 JAR을 로컬 함수 실행기에 올려 Pub/Sub 이벤트 -> 200.

## 배포 (오너 작업)
ADR 0015의 판정 함수에 더해:
```
gcloud pubsub topics create coup-sweep
gcloud functions deploy coup-sweep --gen2 --runtime=java21 --region=<Firestore 위치> \
  --source=server/build/deploy --entry-point=io.github.lhd980820.coup.server.SweepFunction \
  --trigger-topic=coup-sweep --memory=512Mi
gcloud scheduler jobs create pubsub coup-sweep --location=<Firestore 위치> \
  --schedule="*/5 * * * *" --topic=coup-sweep --message-body=sweep
```
Cloud Scheduler API를 켠다. 순서는 ADR 0015와 같다: **함수 둘 -> 규칙 -> 앱**. 새 규칙은 방 쓰기에 서버 시각을 요구하므로 옛 앱의 방 쓰기는 거부된다(같은 때 배포).

## 한계
- ~~버려진 판의 게스트 화면~~ → 해결(후속 커밋): 게임 문서가 `ABANDONED`가 되면 게스트 세션의 연결 상태가 `ABANDONED`(되돌아가지 않음)가 되고,
  화면은 기권 버튼·연결 배너 대신 "판이 끝났어요 — 방장이 오래 돌아오지 않아 서버가 끝냈고 내 레이팅은 그대로" 안내와 "로비로"를 띄운다(뒤로 가기도 같은 길).
  대기실이 아니라 로비로 간다 — 그 방은 게임 중인 채로 남았다가 서버가 닫고, 게스트는 게임 중인 방을 떠날 수 없기 때문이다. 기억해 둔 방도 지워 다시 켜도 돌아가지 않는다.
  테스트: 전송 1(연결 상태가 `ABANDONED`가 되고 되돌아가지 않음), 화면 2(실제 정리로 끝낸 판 -> 안내 -> 로비 알림 -> 재시작해도 그대로, 뒤로 가기), 변이 6종 모두 검출.
- 방장 쪽: 10분 넘게 끊겼다 돌아온 방장 앱은 쓰기가 거부될 뿐 화면은 판이 이어지는 것처럼 보인다(방장 세션은 게임 문서 상태를 보지 않는다). 앱을 다시 켜면 이어 가지 않는다.
- 방장 기기의 네트워크가 10분 넘게 끊기면 그 방장은 진다(의도적으로 버린 것과 구별할 수 없다).
- 로비 숨김은 기기 시계로 판단한다(서버 시각과 크게 어긋난 기기는 방을 일찍/늦게 숨길 수 있다). 실제로 닫는 것은 서버 시각이다.
- 밀리초 섞기는 방장이 서버 시각을 정확한 밀리초로 맞출 수 있으면 약해진다(네트워크 흔들림 때문에 현실적으로 어렵다). 더 강하게 하려면 서버 시드(위 "다른 선택지").
